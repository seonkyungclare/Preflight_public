# Preflight 분석 결과 작성 규칙

> 적용 대상: Preflight 가 내놓는 모든 분석 문자열(요약, 섹션 판정, 체크리스트, PO 질문, UX 제안)과 결과 화면 라벨
> 원본: 이 문서. 프롬프트 상수(`src/lib/analyze-v3.ts` 의 `WRITING_STYLE`)와 결과 화면 라벨은 이 문서를 따름
> 기준: 한국어 사내 문서 작성 규칙(2026-09-21 PO 제공) + 초심자 배려 규칙

---

## 1. 문체

| 규칙 | 적용 | 예시 |
| :--- | :--- | :--- |
| 개조식 | 모든 본문은 명사형 종결(~함, ~임, ~필요, ~미정의) 또는 명사구 | "0건일 때 표시 내용 미정의" |
| 경어체 금지 | "~합니다", "~주세요" 사용 안 함 | ✗ "적어주세요" → ✓ "기재 필요" |
| 예외: PO 질문 | 의문문 유지 | "담당 MD 를 별도 Actor 로 정의할까요?" |
| 예외: 선택지 | 명사구 | "별도 Actor 로 정의(권한 분리)" |
| 한 항목 한 생각 | 문자열 하나에 한 가지 사실 | 60자 이내 |

## 2. 항목 구조 (체크리스트)

체크리스트 항목은 세 칸으로 나눠 씀. 한 칸에 한 문장(명사형).

| 칸 | 내용 | 예시 |
| :--- | :--- | :--- |
| issue | 무엇이 없는가 | "SC-11 검토 대기 목록에서 배정 건 0건일 때 표시 내용 미정의" |
| user_impact / risk | 그래서 무슨 일이 생기는가 | "심사자가 오류 여부 판단 불가" |
| suggestion | 무엇을 채울 것인가 | "안내 문구와 새로고침 버튼 기재 필요" |

## 3. 제목·라벨

- 개념어 명사구로 작성: 구성, 현황, 구조, 담당, 시사점, 미확인 사항
- 금지 형태: "~것", "~는가", "누가 무엇을"
  - ✗ "가장 먼저 채울 것" → ✓ "우선 보완 항목"
  - ✗ "이 PRD 로 시작할 수 있나요?" → ✓ "착수 가능 여부"
  - ✗ "본문에 등장하지만 정의되지 않은 Actor" → ✓ "미정의 Actor"
- 숫자는 괄호로 뒤에: 미정의 Actor(3), 우선 보완 항목(3), 광고 상품 구성(7종)

## 4. 표현 금지 목록

| 금지 | 대체 |
| :--- | :--- |
| "수 + 개의 + 명사": 세 개의 층, 두 개의 스택 | 3계층, 2종 시스템 |
| 영어 은유 직역: ~가 만나는 면, 한 다리로 서 있다, ~위에서 조정된다, ~에서 만난다 | 사실 서술 |
| "하나는 ~, 하나는 ~" 구조 | 항목 나열 또는 표 |
| 대명사 "그것" | 지칭 대상을 명사로 반복 |
| 엠대시(—) | 쌍점(:) 또는 괄호 |
| 영어 UX 용어 단독 사용 | 한글 풀이 우선, 필요 시 괄호에 원어. 원칙 이름은 UX 제안에서만 |
| 축약 ID 단독 사용 | 첫 등장 시 이름 병기: "SC-12 신청 상세", "화면 요구사항(8번 섹션)" |

## 5. 자기 점검

- 작성 후 위 규칙 위반을 스스로 점검하고 수정함
- 수정 항목 목록은 결과에 싣지 않음(출력 길이 절약). 점검은 내부 단계

## 6. 용어집 (초안, 2026-09-21)

외래어·사내 용어는 아래 표기를 따름. 추가·수정은 이 표에서 관리.

### 6-1. 사람·주체

| 표기 | 지양 | 뜻 |
| :--- | :--- | :--- |
| Actor | 액터, 사용자 유형, 역할 | 권한이 구분되는 사용자 유형. 시스템 포함 |
| 파트너 PO | 파트너, 브랜드 담당자 | 입점을 신청하는 브랜드·입점사 담당자 |
| 대행사 | 에이전시 | 파트너를 대리하는 외부 주체 |
| 담당 MD | MD, 사업 담당 | 브랜드 적합성을 심사하는 사업 담당자 |
| 운영 심사자 | 운영자, 심사자, 내부 담당자 | 표준 심사·승인·반려·보류 담당 |
| HO | 본사 운영자 | 등록 자료 검수 담당 |
| 시스템 | 배치, 자동 처리 | 배치·자동 전이 등 사람이 아닌 처리 주체 |
| PO | 기획자, PM | 요구사항 결정 권한자 |
| 디자이너 | PD | 화면 설계 담당 |
| 개발자 | 엔지니어, FE/BE | 구현 담당 |
