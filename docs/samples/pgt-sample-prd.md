## 2. 용어 정의

| 용어 | 정의 | 이 과제에서의 범위 |
| --- | --- | --- |
| 신청 (Application) | 파트너가 입점을 위해 제출하는 공통폼 1건. application_id 로 식별 | 플랫폼별 상태를 병렬 보유 (1:N) |
| 공통폼 | 플랫폼(MSS·29CM)에 공통으로 쓰는 입점 신청 양식 | 사업자 정보·브랜드 정보·담당자 정보 3개 섹션 |
| 심사 | 신청의 적합성·표준 요건을 검토해 승인/반려/보류를 결정하는 단계 | 적합성 심사(담당 MD) → 표준 심사(운영 심사자) 순차 |
| 보류 (HOLD) | 서류 미비 등 보완 가능한 사유로 재제출을 요청한 상태 | 14일 무응답 시 EXPIRED |
| 반려 (REJECT) | 보완 불가 사유로 거절된 상태 | Bypass 대조 후 매칭 시 예외 입점 |
| Bypass | 거절 건 중 예외 입점 대상으로 사전 등록된 사업자 리스트 대조 | 리스트 관리는 사업팀 수기 |
| SOR | 파트너 정보 원장(System of Record). 신청 데이터가 최종 적재되는 저장소 | 승인 건만 적재 |
| 외부 시스템 | 승인 결과를 전달받는 플랫폼 마스터(업체·브랜드 생성) | 일 1회 배치 송신 |
| EXPIRED | 파트너 대기 상태에서 무응답으로 만료된 종료 상태 | 보류 14일 |

### 5.3 이번 Milestone 도달선 (26.11)

> 파트너 PO는 파트너센터에서 공통폼 신청서를 직접 작성해 제출하고, 신청 관리 목록에서 현재 상태를 확인할 수 있다. 보류·반려된 건은 사유를 보고 수정해 재제출할 수 있다. 담당 MD는 배정된 건의 브랜드 적합성을 먼저 판정하고, 운영 심사자는 적합 건을 단건으로 검토해 승인·반려·보류한다. 승인된 건은 HO가 등록 자료를 검수한 뒤 다음 날 새벽 배치로 외부 시스템에 반영된다.

## 7. 시스템 요구사항 (Product Requirement)

### A. 전체 흐름 지도

```
SUBMISSION (신청) → EVALUATION (심사: 적합성 → 표준) → REGISTRATION (등록·검수) → COMPLETION (완료) → 외부 반영
                        ├─ HOLD (보류) → EVALUATION 재진입 / EXPIRED
                        └─ REJECT (거절) → Bypass 대조 → 매칭 시 REGISTRATION / 미매칭 시 종료
```

### A-2. 단계별 상태 변경

| 상태 | 의미 | 진입 (트리거) | 다음 상태 | 주체 |
| --- | --- | --- | --- | --- |
| DRAFT | 임시저장 | 파트너 PO [임시저장] | SUBMISSION | 파트너 PO |
| SUBMISSION | 신청 접수 | 파트너 PO [제출] | EVALUATION | 파트너 PO |
| EVALUATION | 심사 (적합성 → 표준) | SUBMISSION 적재 후 담당 MD 자동 배정 | REGISTRATION (승인) / HOLD (보류) / REJECT (거절·부적합) | 담당 MD · 운영 심사자 |
| HOLD | 보류 (보완 재심) | 운영 심사자 [보류] | EVALUATION (재제출) / EXPIRED (14일 무응답) | 파트너 PO (보완) · 시스템 (만료) |
| REJECT | 거절 | 담당 MD [부적합] · 운영 심사자 [반려] | REGISTRATION (Bypass 매칭) / 종료 | 시스템 (Bypass 대조) |
| REGISTRATION | 등록 자료 검수 | 승인 이벤트 · Bypass 매칭 | COMPLETION (검수 통과) / REGISTRATION (검수 반려 재제출) / EXPIRED (보완 14일 무응답) | HO |
| COMPLETION | 완료 | HO [검수 통과] | 종료 (외부 반영 후 external_synced_at 기록) | 시스템 |
| EXPIRED | 무응답 만료 | HOLD 14일 · REGISTRATION 보완 14일 | 종료 | 시스템 |
| WITHDRAWN | 회수 | 파트너 PO [회수] (EVALUATION 이전만) | 종료 | 파트너 PO |

### B. 영역별 정책

**P-01 자동 배정**
- ① 정의: SUBMISSION 적재 시 담당 MD 를, 적합 판정 시 운영 심사자를 시스템이 배정한다.
- ② 정책표

| 축 | 항목 | 정책 | 비고 |
| --- | --- | --- | --- |
| 진입 | 트리거 | SUBMISSION 생성 이벤트 | |
| 검증 | 배정 규칙 | 브랜드 카테고리 → 담당 MD 매핑표 (운영 어드민에서 관리) | 매핑 없는 카테고리는 기본 MD 풀에 라운드로빈 |
| 검증 | MD 부재 | 휴가 등 부재 플래그 시 다음 MD | |
| 산출 | 배정 결과 | assignee_id · assigned_at 기록, 담당 MD 에게 어드민 알림 | |

**P-02 적합성 판정**
- 적합/부적합 판정은 담당 MD 만 가능. 부적합 시 사유 필수(최소 10자).
- 부적합 → REJECT → P-04 Bypass 대조.

**P-03 승인**
- 승인 시 REGISTRATION 전이, HO 자동 배정(등록 담당 풀 라운드로빈), 파트너 PO 에게 메일 알림.
- 이미 처리된 건(상태 ≠ EVALUATION)에 승인 요청 → 409 반환, "이미 처리된 신청입니다. 현재 상태: {상태}" 안내.
- 동시 처리: 상세 진입 시 version 을 내려주고 처리 요청에 version 을 함께 보낸다. 불일치 시 409.

**P-04 거절 · Bypass**
- REJECT 진입 시 시스템이 Bypass 리스트(사업자번호 기준)와 대조. 매칭 시 REGISTRATION 으로 예외 진입, 미매칭 시 종료.
- Bypass 리스트는 사업팀이 운영 어드민 > 설정에서 관리. 대조 로그(matched, list_version) 기록.

**P-05 보류 · 재제출**
- 보류 사유 필수(최소 10자). 보류 시 파트너 PO 메일 알림, HOLD 진입 시각 기록.
- 재제출은 같은 application_id 유지. 재제출 시 담당 MD 재판정 없이 운영 심사자 단계로 복귀.
- HOLD 14일 경과 → 시스템이 EXPIRED 전이. 만료 3일 전 리마인드 메일 1회.

**P-06 검수**
- 검수 통과 시 COMPLETION. 검수 반려 시 REGISTRATION 유지 + 보완 사유 메일. 보완 14일 무응답 → EXPIRED.

**P-07 알림**
- 상태 전이(EVALUATION 진입 · HOLD · REJECT · REGISTRATION · COMPLETION · EXPIRED)마다 파트너 PO 담당자 이메일로 발송.
- 발송 실패 시 3회 재시도(5분 간격), 소진 시 알림 로그에 failed 기록. 발송 실패가 상태 전이를 막지 않는다.

**P-08 데이터·표시·시간 공통**
- 데이터: 목록은 20건 페이징, 0건이면 빈 상태. 동일 사업자번호 진행 중 신청은 1건만 허용.
- 표시: 브랜드명 40자 초과 시 말줄임 + 툴팁. 금액 없음. 미입력 필드는 "-", 0 은 "0" 으로 구분 표기. 날짜는 YYYY.MM.DD HH:mm (KST).
- 네트워크: 조회 실패 시 오류 안내 + [다시 시도]. 처리 요청 타임아웃 10초, 중복 클릭 방지(버튼 비활성).
- 외부 연계: §9 참조.
- 권한: §3 참조. 세션 만료 시 처리 요청은 401 → 로그인 후 복귀.
- 입력: 사업자번호 10자리 숫자·체크섬 검증, 이메일 형식, 파일 10MB 이하 PDF/JPG/PNG.
- 상태: 이미 처리된 건 재처리 → 409. 작성 중 이탈 → 이탈 확인 + 임시저장.
- 시간: HOLD·보완 14일 기준은 KST 자정 배치로 만료 처리. 처리 중 파트너가 회수하면 version 불일치로 409.
